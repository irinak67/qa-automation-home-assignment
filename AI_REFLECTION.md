# AI Use Reflection

Working draft based on work completed so far. Update after implementing and running the email tests.

- **Scope of assistance:** I used AI to turn manual observations into candidate scenarios, generate Playwright tests, inspect live DOM structure, and investigate execution failures. My manual exploration supplied the behavioral evidence, including the difference between new-account verification and an existing-account sign-in notification.
- **Verification:** Generated tests were checked against the live canary application, not accepted from screenshots alone. The first expanded run passed four tests and failed three. After diagnosis and correction, all seven implemented registration tests passed in Chromium, and TypeScript checking passed.
- **Concrete correction:** AI initially expected nickname errors immediately after `fill`, extending an observation about password feedback to a different field. Two tests failed because the expected messages did not appear. A focused probe showed no nickname error after input or blur, but an error after submission. The tests were corrected to submit otherwise valid details with an invalid nickname before checking feedback; both subsequently passed.
- **Engineering judgment:** I checked browser-native email validity rather than relying on a tooltip's English text. I also corrected the preliminary duplicate-email expectation after inspecting the actual email: the flow offered sign-in information rather than an inline existing-account error. I did not treat password strength as a function of length alone or infer backend account uniqueness from a UI message.
- **Scope and remaining limitations:** Seven registration tests are implemented. Three planned email tests require programmatic mailbox access and independent account data. Successful manual verification has been observed, but automated delivery and verification are not yet validated. The paste failure remains an investigation finding; it has not been reproduced by an automated test.
